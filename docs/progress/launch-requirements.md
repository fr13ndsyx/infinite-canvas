## 需求 3：提示词模块改造

### 3.1 废弃 GitHub 同步，改后台手动维护

**确认决策**：GitHub 同步链路整条删除，包括数据库 `PromptSource` 表。理由：项目不兼容旧数据；同步功能确认废弃；`Prompt.source` 字段保留为普通来源标签（导入时自定义填写），不影响现有数据展示。

**删除清单**：
- 后端：`Go/model/prompt.go` 的 `PromptSource` / `PromptSourceOption` 结构、`Go/service/prompt_fetch.go`、`Go/service/prompt_sync_scheduler.go`、`main.go` 中的 `StartPromptSyncScheduler()` 调用
- 后端路由：`/api/admin/prompt-sources` 全部 6 个接口
- 前端：管理后台提示词源管理页面、`next/src/services/api/admin-prompt-sources.ts`
- 文档：`docs/overview/third-party-prompt-repositories.md` 同步删除或改写

**新增能力（管理后台）**：
- 提示词单条增删改（沿用现有 `AdminSavePrompt` / `AdminDeletePrompt` 链路扩展）
- **JSON 文件批量导入**：JSON 描述文件 + 对应图片/视频媒体文件，后台上传后批量入库；媒体文件走现有存储链路（S3 兼容 / R2）
- 想更新内容时重新上传导入即可（"定时更新"= 人工定期上传，无系统定时任务）

### 3.2 三大模块分类

- 提示词列表页顶部三个 Tab：**图片 / 视频 / 电影级**（"电影级"指电影级视频）
- `Prompt` 模型新增 `category` 字段：`image` / `video` / `cinematic`，加索引
- 现有 `tags` 保留作为二级筛选
- 前端列表页、后台管理页、批量导入 JSON 结构同步支持 `category`

### 3.3 会员专属提示词（后续阶段，本轮不做）

- 本轮只做上传改造与三模块分类，**不做**专属标记
- 后续与需求 2 会员/支付体系联动实施：提示词可标记会员专属，非会员可见不可用

## 需求 4：技能模块（新增）

### 定位

类 Coze/扣子的预置 AI 能力包，绑定画布节点类型，一键调用。技能全部由管理后台预置，普通用户不能自建，无会员专属标记。

**技能 = 节点类型 + 预置 prompt 模板 + 一键执行**，与提示词（"参考复制"）执行语义不同，使用**独立 `skills` 表**，不复用 Prompt。

### 数据模型（`skills` 表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 主键 |
| nodeType | string | `text` / `image` / `video`，加索引 |
| name | string | 技能名（如"运镜 - 轨道右移"） |
| description | string | 一句话说明（如"设备沿轨道匀速水平向右平稳移动"） |
| prompt | text | 预置 prompt 模板 |
| coverUrl | string | 封面/示意图（可选） |
| sortOrder | int | 排序 |
| enabled | bool | 上下架 |
| createdAt / updatedAt | string | 时间戳 |

### 交互（前端画布）

- 入口：节点底部助手栏新增"技能"按钮，**放在提示词按钮旁边**
- 点击弹出技能面板，按当前节点类型过滤展示（名称 + 说明）
- 点击技能后：**prompt 注入节点输入框，用户可见可改**（透明形态，不做隐藏叠加）

### 接口

- 公开：`GET /api/skills?nodeType=`（画布节点读取）
- 管理后台：`/api/admin/skills` CRUD

### 参考技能（首批预置内容）

- 文本节点：翻译（中英双向互译）、文本扩写丰富
- 图片节点：16 宫格连贯分镜图、电影级光影矫正
- 视频节点：运镜 - 轨道右移、运镜 - 环绕拍摄

## 需求 1：注册登录优化（收尾阶段）

**方向**：邮箱验证码 / 小程序扫码登录 / 手机号验证三选一，倾向**小程序扫码登录**。

**技术原理**：网页生成带 scene 参数的小程序码 → 用户扫码进入小程序点确认 → 网页轮询拿 token 完成登录。`User` 表已预留 `WechatID` 字段。

**前置条件（需用户确认）**：
- [ ] 已有**已发布的微信小程序**（扫码登录必须以线上小程序为载体）
- [ ] 小程序主体是个人还是企业/个体户（影响能力与后续支付）
- [ ] 服务器域名已完成 **ICP 备案**（微信强制要求）

现有用户名+密码注册登录保留还是替换，动工前再定。

## 需求 2：支付系统（收尾阶段）

**现状基础**：算力点体系已完整（`Credits` 余额 + `CreditLog` 流水 + 平台渠道预扣/失败返还），支付只需做"充值入口"对接现有体系。

**待确认问题**：
- [ ] 收费模式：充值算力点（改动最小，直接对接 Credits）还是订阅会员（需新增会员体系；会员专属提示词依赖此决策）
- [ ] 收款渠道：微信支付商户号 / 支付宝 / 第三方个人支付（个人身份无法开通微信/支付宝商户，与需求 1 的小程序主体问题联动）

## 实施顺序建议

1. **需求 3**：提示词模块改造（删除 GitHub 同步 + 后台维护 + JSON 批量导入 + 三模块分类）
2. **需求 4**：技能模块（skills 表 + 后台 CRUD + 画布技能按钮与面板）
3. 项目运行验证没问题后，启动需求 1（小程序扫码登录）与需求 2（支付）

每步完成按项目规范更新 `docs/progress/todo.md` 与 `docs/progress/pending-test.md`。
