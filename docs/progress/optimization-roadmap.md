# 项目问题与可优化路线

本文档基于当前仓库源码、运行配置和进度文档整理，区分需要优先修复的缺陷/风险、UI 视觉布局优化与可选优化项。涉及文件路径均以仓库根目录为基准。

## 一、优先修复

### P0：生产构建忽略 TypeScript 错误

- 证据：`next/next.config.ts` 设置 `typescript.ignoreBuildErrors = true`。
- 风险：类型错误可以进入生产构建；`next/tsconfig.json` 的 `strict: true` 无法发挥质量门禁作用。
- 建议：正式构建关闭该选项，并增加 `typecheck`（`tsc --noEmit`）和 CI 检查。

### P0：多个接口没有请求体/响应体大小限制

- 证据：`Go/handler/ai.go` 的 `readAIRequest()`、`Go/handler/storage.go` 的 `UploadFile()` 和 `ProxyImage()` 直接读取完整 body。
- 风险：超大 JSON、multipart、图片或代理响应可能造成内存暴涨；公开图片代理还可能被用于带宽滥用。
- 建议：为 AI 请求、文件上传、图片代理设置独立上限，使用 `http.MaxBytesReader`/`io.LimitReader`，超限返回 413。

### P0：生图数量 `n` 没有后端上限

- 证据：`Go/handler/ai.go` 的 `readAIRequestCount()` 读取 `n` 后直接参与算力点计算。
- 风险：恶意客户端可以绕过前端限制提交超大数量，造成异常预扣、整数溢出或上游压力。
- 建议：后端统一校验 `1 <= n <= 10`，在计费前完成边界和溢出检查。

### P1：对象存储文件接口默认公开

- 证据：`Go/router/router.go` 将 `/api/files/:id` 和 `/api/files/:id/content` 注册为无鉴权路由；`Go/handler/storage.go` 未校验对象所有者。
- 风险：拿到对象 ID 即可读取文件内容和存储元数据。
- 建议：区分公开媒体与用户私有文件；私有文件要求登录并校验 `CreatedBy`；对外部 AI 使用短期签名 URL 或独立的公开引用接口。

### P1：对象存储回退读取存在 SSRF 风险

- 证据：`Go/service/storage.go` 的 `DownloadStorageObject()` 在 S3 读取失败后使用 `http.DefaultClient.Get(object.PublicURL)`；该 URL 可能来自用户自定义 Provider。
- 风险：恶意 `PublicBaseURL` 可能诱导服务端访问内网地址。
- 建议：统一使用 `SafeProxyHTTPClient()` 或在回退前进行严格的 URL/IP 校验；更稳妥的是禁止回退到任意公共 URL。

### P1：存储容量和 AI 日志清理调度器没有启动

- 证据：`Go/service/storage.go` 定义了 `StartStorageCapacityScheduler()`，`Go/service/ai_log.go` 定义了 `StartAILogCleanupScheduler()`，但 `Go/main.go` 没有调用它们。`SaveSettings()` 中的 Refresh 调用在 scheduler 未创建时不会生效。
- 影响：启用容量巡检或日志清理后，定时任务仍不会运行。
- 建议：在 `Go/main.go` 启动阶段显式启动两个 scheduler，并记录启动状态和 cron 配置。

### P1：画布删除失败时可能被远程同步重新恢复

- 证据：`next/src/app/(user)/canvas/components/canvas-delete-projects-dialog.tsx` 和 `next/src/app/(user)/canvas/[id]/canvas-client-page.tsx` 对远程删除请求使用 fire-and-forget，失败被吞掉，但本地项目立即删除。
- 风险：网络失败时服务端项目仍存在，下次同步会把项目重新合并回来。
- 建议：远程删除成功后再删除本地，或增加待删除状态/删除墓碑；失败时明确提示用户。

### P1：登录、注册、AI 和代理接口缺少限流

- 证据：当前 Go 路由和 middleware 中未发现统一的 IP、用户或接口级限流实现。
- 风险：登录暴力破解、批量注册、AI 额度滥用、代理带宽滥用和存储攻击。
- 建议：至少为登录/注册、AI 生成、图片代理、文件上传增加基础限流、并发限制和单用户额度。

## 二、UI视觉布局优化

### P1：窄屏下左右面板与底部工具栏互相挤压

- 证据：左侧面板最小宽度为 220px（`next/src/app/(user)/canvas/components/canvas-side-panel.tsx`），右侧 Agent 面板最小宽度为 390px（`next/src/app/(user)/canvas/components/canvas-assistant-panel.tsx`），底部工具栏固定使用 `left: 300`（`next/src/app/(user)/canvas/components/canvas-toolbar.tsx`）。
- 影响：768px 及以下窗口中画布可用区域过窄，工具栏只能横向滚动，甚至可能遮挡节点。
- 建议：在 1024px 以下收起左侧面板或改为抽屉；在 768px 以下将 Agent 面板改为底部/全屏抽屉；工具栏边距根据实际面板宽度计算，并提供移动端精简菜单。

### P1：节点编辑面板靠近边缘时可能被裁剪

- 证据：画布根节点使用 `overflow-hidden`，节点编辑面板固定从节点下方以 580px 宽度展开（`next/src/app/(user)/canvas/components/infinite-canvas.tsx`、`next/src/app/(user)/canvas/components/canvas-node.tsx`）。
- 影响：画布底部或右侧的节点打开编辑面板后，内容可能超出视口而不可见。
- 建议：将节点编辑面板通过 Portal 渲染，在上下左右方向进行碰撞检测；增加最大高度和内部滚动。

### P1：浮层层级和裁剪规则不统一

- 证据：侧栏、节点工具条、右键菜单、创建菜单、设置弹窗和全屏预览分别使用 `z-[60]`、`z-[70]`、`z-[80]`、`z-[120]`、`1200/1300` 和 `z-[2000]`。
- 影响：嵌套在 transform 或 `overflow-hidden` 容器中的菜单可能被遮挡，浮层之间的优先级也难以维护。
- 建议：建立统一的浮层层级 token；页面级菜单和弹窗统一挂载到 Portal 根节点。

### P1：触控操作和触摸目标尺寸不足

- 证据：画布交互主要依赖鼠标滚轮、空格键和 Pointer Events；工具栏按钮通常为 32×32px，侧栏操作按钮为 24×24px，部分节点操作依赖 `group-hover` 才显示。
- 影响：移动端无法直观完成平移、缩放和节点操作，小尺寸按钮也容易误触。
- 建议：明确设置 `touch-action` 并支持双指缩放；触摸设备将主要按钮扩大到 40–44px；将 hover-only 操作改为选中后显示或提供常驻入口。

### P1：图标按钮和标题编辑的键盘可用性不足

- 证据：Agent 面板头部多个图标按钮仅依赖 Tooltip，没有显式 `aria-label`；画布标题和节点标题主要通过双击进入编辑。
- 影响：屏幕阅读器难以识别操作含义，键盘用户无法进入标题编辑。
- 建议：为图标按钮补充 `aria-label`，为侧栏按钮补充 tab 语义；增加 Enter、Space 或 F2 编辑标题的入口。

### P2：画布主题仍存在硬编码颜色

- 证据：节点选中色固定为 `#2f80ff`，节点悬浮工具条固定为深色背景，小地图按节点类型使用固定十六进制颜色。
- 影响：浅色/深色主题下的选中态、工具条和小地图颜色不完全协调，部分对比度无法统一管理。
- 建议：将选中色、媒体类型色、悬浮工具条背景和状态色补充到 `canvasThemes`，组件只读取主题 token。

### P2：底部工具栏功能过于平铺

- 证据：工具栏同时展示移动、撤销、重做、多个节点类型、上传、素材、外观及清空等十余项操作。
- 影响：功能分组不明显，移动端需要长距离横向滚动，危险操作也与普通操作距离较近。
- 建议：保留高频操作，将节点创建、素材管理和画布设置分别收进二级菜单；将“清空画布”与普通操作隔离。

### P2：左侧面板信息密度较高

- 证据：侧栏同时包含节点、资产、提示词库、搜索、类型筛选、分类折叠和分页，并存在多个独立滚动区域。
- 影响：220px 宽度下文本大量截断，用户需要在多个筛选层级之间切换。
- 建议：保留“节点 / 资产 / 提示词库”一级入口，减少同时显示的筛选项；窄屏优先显示节点列表，其余改为抽屉。

### P2：大画布下连接线渲染范围过大

- 证据：连接线使用固定 10000×10000 的 SVG，并遍历当前全部 connections。
- 影响：节点和连线数量增加后，平移、缩放和选中操作可能掉帧。
- 建议：按视口裁剪节点和连接线；远离视口时延迟渲染或降低动画细节。

### P2：动画没有适配减少动态效果设置

- 证据：画布面板、批量图片和工具条存在 300–500ms 动画，但全局样式中未发现 `prefers-reduced-motion` 分支。
- 影响：对动态敏感的用户可能产生不适，低性能设备也会承受额外动画开销。
- 建议：在 `prefers-reduced-motion: reduce` 下关闭或缩短画布动画。

### P2：空画布引导在小屏幕上占用空间较大

- 证据：空画布状态使用大字号文案、多个大按钮和较大的间距。
- 影响：小屏幕中引导内容可能与底部工具栏、缩放控件争夺可视空间。
- 建议：桌面端保留完整引导，移动端改为简化卡片或单一“开始创建”入口。

本节结论基于源码结构审查，尚未启动前后端进行浏览器截图验证。实施前应至少覆盖 375px、768px、1024px、1440px，以及浅色/深色主题。

## 三、后台管理布局与 UI 重构方案

### 3.1 当前问题判断

- `next/src/app/(admin)/admin/layout.tsx` 使用固定 232px 侧栏和 56px 顶栏，导航、品牌、账户操作和退出入口层级较平。
- `next/src/app/(admin)/admin/page.tsx` 直接跳转到用户管理，没有后台总览页，管理员缺少系统健康状态和关键指标入口。
- 用户、素材、提示词等页面重复使用 `main + Card + Form + Table` 结构，页面之间的标题、筛选区、操作区和表格密度不统一。
- 用户页使用 ProTable，其他资源页多使用普通 Table，工具栏、分页、密度和列操作体验不一致。
- 设置、渠道、存储、日志等复杂页面依赖大量内联样式和嵌套 Card，信息层级不清晰，容易形成“卡片堆叠”。

### 3.2 设计方向：编辑部式控制台

采用“编辑部式控制台（Editorial Control Room）”作为后台视觉方向：

- 基础色以暖灰纸张色、炭黑和低饱和灰为主，延续无限画布的中性品牌气质。
- 使用一个明确的信号色区分主要操作和系统状态，避免每个页面都使用不同的高饱和颜色。
- 页面保留数据密度，但通过标题层级、留白、分组和状态标记建立秩序，不使用大面积渐变或装饰性阴影。
- 卡片采用细边框、14px 圆角和极轻阴影；重要操作采用实心按钮，次要操作采用文字/描边按钮。
- 正文继续沿用项目中文字体栈，页面标题可使用更有辨识度的字重和字距，避免标题与表格文本同质化。

### 3.3 新版后台框架

桌面端建议采用可收缩侧栏 + 全局顶栏 + 统一内容容器：

```text
┌────────────────┬──────────────────────────────────────────────┐
│ Logo / 控制台  │ 面包屑        页面标题              搜索 账户 │
│                ├──────────────────────────────────────────────┤
│ 总览           │ 页面说明                         主要操作      │
│ 运营           │ ┌────────┐ ┌────────┐ ┌────────┐              │
│  AI 平台       │ │ 指标卡 │ │ 指标卡 │ │ 指标卡 │              │
│ 内容库         │ └────────┘ └────────┘ └────────┘              │
│ 基础设施       │ 筛选工具栏 / 批量操作                         │
│                │ 数据表格或内容网格                            │
│ 画布入口       │                                                │
│ 账户与系统状态 │                                                │
└────────────────┴──────────────────────────────────────────────┘
```

具体规则：

- 侧栏宽度 248px，折叠后 72px；移动端改为抽屉，不占据永久空间。
- 顶栏高度 64px，左侧显示面包屑和当前页面标题，右侧提供全局搜索、主题切换、帮助和账户菜单。
- 内容区最大宽度建议为 1440px，桌面端内边距 28–32px，窄屏缩小为 16px。
- 统一提供 `AdminPageHeader`、`AdminFilterBar`、`AdminSection`、`AdminDataTable`、`AdminDetailDrawer` 等基础组件，页面不再自行拼接重复 Card。
- “前往画布”和“退出登录”放到账户菜单或侧栏底部的统一区域，避免顶栏和侧栏重复放置同类入口。

### 3.4 信息架构调整

建议将现有导航调整为：

1. **总览**：系统指标、渠道健康、近期活动和快捷操作。
2. **运营**：用户管理、算力点日志、AI 调用日志。
3. **AI 平台**：渠道与模型、模型能力与定价。
4. **内容库**：提示词管理、素材库。
5. **基础设施**：存储设置、系统偏好。
6. **高级配置**：原始 JSON、排障和迁移工具，并使用危险操作提示。

“模型管理”建议改为“渠道与模型”，明确该页面既管理渠道，也管理模型列表；“开放与定价”建议改为“模型能力与定价”，更符合实际功能。

### 3.5 首页总览方案

将 `/admin` 从重定向页改为真正的后台首页，首屏只展示需要管理员快速判断的信息：

- 关键指标：用户总数、近 24 小时 AI 调用量、算力点消耗、存储占用。
- 渠道健康：在线/异常渠道数量、最近一次测试时间、失败原因摘要。
- 内容概况：提示词数量、素材数量、最近新增内容。
- 最近活动：用户注册、渠道修改、模型测试、存储告警等时间线。
- 快捷操作：新增渠道、添加提示词、调整模型价格、查看异常日志。

### 3.6 具体页面改版建议

- **用户管理**：增加用户数/活跃用户/禁用用户指标；筛选区改为单行工具栏；表格操作收敛为“编辑”和更多菜单；编辑用户改用分区 Drawer，算力点调整单独成组并显示变更说明。
- **渠道与模型**：表格增加渠道健康状态、协议、模型数量和最近测试结果；新增/编辑渠道 Drawer 按“连接信息 / 模型 / 请求策略 / 高级备注”分组；模型选择器保留搜索、全选和当前已选数量。
- **模型能力与定价**：按图片、视频、文本、音频分组；价格、能力开关和默认模型在同一模型行内呈现；避免多个大 Card 纵向堆叠。
- **提示词与素材库**：提供“表格 / 网格”视图切换；网格显示封面、标题、分类和更新时间；批量导入、批量删除和新增操作固定在工具栏右侧；详情使用右侧 Drawer，不用多层 Modal。
- **AI 调用日志 / 算力点日志**：增加时间范围、状态、渠道、模型等筛选条件；日志详情使用 Drawer 展示请求摘要、耗时、错误信息和原始 JSON；危险清理操作与普通查询操作隔离。
- **存储设置 / 系统偏好**：使用左侧设置目录 + 右侧分区表单；每个设置区显示用途说明、当前状态和保存反馈；高风险开关增加影响范围说明。
- **高级配置**：突出“仅用于排障和迁移”的警示；编辑器、校验、格式化和保存操作固定在顶部；避免与普通设置页面使用相同的视觉权重。

### 3.7 视觉 Token 建议

将后台专用 Token 集中到 `next/src/lib/app-theme.ts`，页面不再散落硬编码颜色：

- `admin.pageBackground`：暖灰页面背景。
- `admin.surface` / `admin.surfaceRaised`：普通表面和抬升表面。
- `admin.border`：细边框和分隔线。
- `admin.primary`：主要操作色，浅色和深色主题分别定义。
- `admin.signal`：系统健康、提醒和异常状态色。
- `admin.text` / `admin.textMuted`：正文和辅助文本。
- `admin.radius`、`admin.contentMaxWidth`、`admin.sidebarWidth`：统一尺寸规则。

状态颜色必须同时配合文字或图标，不以颜色作为唯一信息；正文对比度至少达到 4.5:1。

### 3.8 响应式与可访问性

- 1440px：完整侧栏、指标卡四列、宽表格。
- 1024px：侧栏可折叠，指标卡两列，筛选条件允许换行。
- 768px：侧栏改抽屉，复杂表格提供横向滚动或卡片化行布局。
- 480px：主要操作固定在页面底部或顶栏，按钮触摸目标不小于 44px。
- 所有图标按钮补充 `aria-label`，所有输入保持可见标签和错误提示。
- 表格、Drawer、Modal 支持键盘操作和 Escape 关闭；动画统一支持 `prefers-reduced-motion`。

### 3.9 实施顺序

1. 先建立后台 Token、AdminLayout、侧栏折叠和统一顶栏。
2. 新增后台总览页，验证整体视觉方向和指标卡样式。
3. 抽取页面头部、筛选工具栏、数据表格和详情 Drawer。
4. 优先改造用户管理、渠道与模型、提示词/素材库等高频页面。
5. 再处理模型能力与定价、日志、存储、系统偏好和高级配置。
6. 最后完成移动端、键盘导航、深色主题和减少动态效果适配。

### 3.10 验收标准

- 所有后台页面使用统一的页面标题、操作区、筛选区和内容容器。
- 不再出现首页进入后台后直接落到用户管理的情况。
- 桌面端侧栏可折叠，移动端不会出现固定侧栏挤压内容。
- 关键页面在 375px、768px、1024px、1440px 下无横向溢出。
- 浅色/深色主题下颜色、边框、表格选中态和状态标签均有足够对比度。
- 用户、渠道、内容和日志页面的新增/编辑/详情交互分别收敛为一致的 Drawer 或 Modal 模式。

## 四、可靠性与部署优化

### P2：Render 使用 SQLite 但未配置持久化磁盘

- 证据：`render.yaml` 使用 `STORAGE_DRIVER=sqlite` 和 `data/infinite-canvas.db`，未配置 Persistent Disk。
- 风险：实例重启、重新部署或迁移可能丢失用户、设置、算力点、任务和同步数据。
- 建议：生产环境优先使用 PostgreSQL；若继续使用 SQLite，必须配置持久化磁盘并验证备份恢复。

### P2：默认管理员密码和默认 JWT 配置不适合生产

- 证据：`.env.example` 中仍使用 `ADMIN_PASSWORD=infinite-canvas`、`JWT_SECRET=infinite-canvas`。
- 风险：未修改默认密码时容易被接管；JWT 使用运行时随机密钥时，服务重启会使旧 token 全部失效。
- 建议：首次启动强制修改管理员密码；生产环境拒绝默认值；要求显式配置稳定的 JWT_SECRET。

### P2：异步任务结果依赖上游临时 URL

- 证据：`Go/model/video_task.go`、`Go/model/canvas_image_task.go` 保存 `VideoURL`/`ImageURL`，前端历史和画布节点会继续引用这些 URL。
- 风险：上游 URL 过期后，历史记录或画布中的媒体无法播放。
- 建议：任务完成后优先下载到对象存储，项目和历史只保存稳定的 `storageKey`，必要时记录 URL 过期时间。

### P2：本地持久化与远程同步逻辑缺少自动化回归测试

- 重点文件：`next/src/app/(user)/canvas/stores/use-canvas-store.ts`、`next/src/stores/use-asset-store.ts`、`next/src/services/image-storage.ts`、`next/src/services/file-storage.ts`。
- 风险：登录合并、删除竞态、多标签页覆盖、媒体引用清理等边界行为容易回归。
- 建议：为 `mergeCanvasProjects()`、`mergeAssets()`、删除同步和 storageKey 生命周期增加单元测试。

## 五、工程质量与维护

### P2：前端缺少类型检查、lint 和测试门禁

- 证据：`next/package.json` 只有 `dev`、`build`、`start`、`format`、`format:check`，没有 `typecheck`、`lint` 或测试脚本。
- 建议：补充最小质量门禁，并在发布前执行前端类型检查、格式检查和 Go 测试。

### P2：架构文档和源码存在历史漂移

- `ARCHITECTURE.md` 仍描述当前源码已移除的提示词同步调度器。
- `docs/overview/repo-structure.md` 列出部分不存在的文件和模块。
- 文档中的数据库表数量与当前 `repository/db.go` 实际 AutoMigrate 的 15 张表不一致。
- README 中仍有旧 `web/` 路径和旧的环境变量复制方式。
- README、`VERSION`、`next/package.json` 的版本号不一致。

建议以当前源码为准统一架构文档、目录树、部署步骤和版本来源。

### P2：用户自带 API Key 的安全边界需要更明确

- 证据：本地渠道模式下，API Key 保存在浏览器并由前端直连 OpenAI 兼容接口。
- 风险：浏览器扩展、恶意脚本、共享设备或不可信部署环境可能读取 Key。
- 建议：在配置界面和部署文档中持续强调该模式适合个人/可信环境；公开多租户部署默认关闭自定义渠道，统一使用服务端渠道。
